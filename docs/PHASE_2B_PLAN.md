# Phase 2B 실행 계획 — TShark 호환성 및 프로토콜 인벤토리

## 승인 배경

2026년 9월 3일 사용자는 Phase 2A 병합과 프리뷰 릴리즈 이후 다음 개발을 계속하도록 명시적으로 지시했습니다. Phase 2B는 승인된 Portable TShark를 자동으로 구하거나 저장소에 포함하지 않으면서, 해당 번들이 제공됐을 때 실제 프로토콜 인벤토리를 안전하게 생성할 수 있는 기반층을 구현합니다.

## 목표

- 승인된 TShark의 `-G fields` 결과를 제한된 UTF-8 텍스트로 읽어 필드 호환성을 검사합니다.
- 저장소에 버전이 고정된 추출 프로파일을 두고 사용자 임의 필드·필터 입력을 허용하지 않습니다.
- `-T fields` 출력 형식을 고정하고 헤더와 각 행을 엄격하게 검증합니다.
- `frame.protocols`를 기반으로 802.11, EAPOL, EAP, RADIUS, DHCP, DNS, ARP, TCP, TLS 등 **프로토콜 존재 여부와 프레임 수만** 집계합니다.
- 결과를 초급 네트워크 엔지니어에게 `관찰됨 / 관찰되지 않음 / 일부만 검사됨 / 판단 불가`로 안내합니다.

## Phase 2B의 범위

### 구현

- TShark 필드 카탈로그 파서
- 버전 고정 JSON 추출 프로파일 로더와 스키마 검증
- 필수·선택 필드 호환성 해석
- 고정 헤더·탭 구분·첫 번째 발생값·따옴표·이스케이프를 사용하는 fields 출력 파서
- 프로토콜 그룹별 관찰 프레임 수, 첫 프레임, 마지막 프레임 집계
- 캡처 길이와 원본 길이를 이용한 TShark 기준 잘림 관찰
- 최대 패킷 수와 최대 출력 바이트 제한
- 취소와 시간 제한이 있는 격리된 TShark 실행 경계
- 승인 번들이 있을 때만 활성화되는 GUI 프로토콜 인벤토리 동작
- 합성 `-G fields` 및 `-T fields` 텍스트와 모의 프로세스만 사용하는 자동 테스트

### 구현하지 않음

- IP, MAC, 사용자 ID, SSID, RADIUS 사용자명 등 식별자 추출
- Raw Payload, 쿠키, Authorization, 자격 증명, 파일 추출
- EAP·RADIUS·DHCP·DNS·TCP 이벤트 상관분석
- 장애 원인 Finding과 상태 머신
- 자유 입력 Display Filter 또는 TShark 옵션
- 실시간·원격 캡처
- TShark 자동 다운로드·업데이트·시스템 설치본 대체
- 승인되지 않은 바이너리를 사용한 통합 테스트

## 출력 안전성

Phase 2B 추출 프로파일은 다음 프레임 메타데이터만 허용합니다.

- `frame.number`
- `frame.interface_id` — 선택 필드
- `frame.cap_len`
- `frame.len`
- `frame.protocols`

IP, MAC, 호스트명, SSID, 사용자명, Payload는 출력 프로파일에 포함하지 않습니다. TShark 표준 오류 원문도 사용자 메시지나 로그에 남기지 않습니다.

## 실행 정책

필드 카탈로그 명령은 다음 고정 구조만 허용합니다.

```text
tshark.exe -n -G fields
```

프로토콜 인벤토리 명령은 다음 고정 구조만 허용합니다.

```text
tshark.exe -n -2 -r <검증된 로컬 캡처> -c <고정 상한>
  -T fields
  -E header=y
  -E separator=/t
  -E occurrence=f
  -E quote=d
  -E escape=y
  -Y <승인 필터>
  -e <승인 필드> ...
```

실행 파일, 캡처, 격리 디렉터리, 매니페스트와 SHA-256은 실행 전후 다시 확인합니다. 표준 출력과 표준 오류는 메모리 상한이 있는 파이프로만 받고 파일로 저장하지 않습니다.

## 판정 경계

- 프로토콜이 관찰되었다는 사실은 해당 단계의 성공 또는 실패를 의미하지 않습니다.
- 프로토콜이 관찰되지 않았다는 사실은 캡처 위치·시간·방향 때문에 누락됐을 수 있으므로 장애 증거가 아닙니다.
- TShark 패킷 상한 또는 Phase 2A 사전 점검 상한에 도달하면 전체 캡처 결과로 표현하지 않습니다.
- 필수 필드가 등록되지 않은 TShark 버전은 호환성 오류로 중단합니다.
- 선택 필드가 없으면 해당 정보만 `판단 불가`로 표시하고 나머지 인벤토리는 계속합니다.

## 완료 기준

- 필드 카탈로그의 P·F 레코드를 엄격하게 구분하고 중복·손상·과대 출력을 거부합니다.
- 프로파일 JSON의 중복 키, 미지 필드, 잘못된 식별자와 필드명을 거부합니다.
- 필수 필드 누락 시 실행하지 않습니다.
- 실제 인벤토리 argv에는 `-n`, `-2`, `-r`, `-c`와 모든 고정 `-E` 옵션이 정확히 한 번 포함됩니다.
- 자유 입력 필터·필드·옵션·실시간 캡처 인자를 통과시키지 않습니다.
- 동일한 합성 fields 출력은 동일한 정규화 JSON을 만듭니다.
- 기존 테스트와 Phase 2B 테스트가 Windows CI에서 통과합니다.
- 승인 TShark 미제공 상태는 계속 `미준비`로 표시하고 기능을 성공한 것처럼 모방하지 않습니다.

## 다음 단계

Phase 2C에서는 Phase 2B의 검증된 필드 프로파일을 확장하여 EAP·RADIUS·DHCP·DNS·ARP·TCP의 개별 이벤트를 생성합니다. 장애 Finding과 접속 상태 머신은 이벤트 정확도와 캡처 한계 테스트가 확보된 이후에 구현합니다.
