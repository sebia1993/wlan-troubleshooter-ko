# Phase 4F 실행 계획 — 단말 가명별 접속 관찰 여정

## 배경

Phase 4E는 원본 MAC·BSSID를 결과에 기록하지 않고 현재 분석 실행에서만 유효한 `DEVICE-N`, `AP-N` 가명을 만듭니다. Phase 4D는 EAP·RADIUS·DHCP·DNS·TCP를 비식별 거래 시도로 정리합니다.

Phase 4F는 Phase 4E가 **단일 단말 근거로 이미 안전하게 연결한 거래만** 단말 가명별 관찰 여정으로 묶습니다. 주소가 없는 RADIUS 거래처럼 단말 근거가 없는 항목을 시간 근접성만으로 끼워 넣지 않습니다.

## 사용자 목표

초급 네트워크 엔지니어가 다음 내용을 한 화면에서 확인할 수 있도록 합니다.

- `DEVICE-N`에서 안전하게 연결된 거래는 무엇인가?
- 실제 패킷 프레임 순서에서 EAP·DHCP·DNS·TCP가 어떤 순서로 관찰됐는가?
- 명시적인 실패 결과가 처음 관찰된 단계는 어디인가?
- 마지막으로 성공 방향 결과가 관찰된 단계는 어디인가?
- 성공·실패·미완료 거래가 한 단계에 함께 있는가?
- Wireshark에서 어떤 프레임을 다시 확인해야 하는가?
- 단말에 연결하지 못한 거래나 모호한 거래는 몇 개인가?

## 입력

Phase 4F는 다음 두 개의 이미 비식별화된 결과만 사용합니다.

```text
Phase 4D transaction_sessions
Phase 4E device_sessions
```

허용 식별자는 다음 형식뿐입니다.

```text
DEVICE-N
AP-N
EAP-N-AN
RADIUS-N-AN
DHCP-N-AN
DNS-N-AN
TCP-N-AN
```

원본 MAC·BSSID·IP·SSID·사용자명·호스트명·포트·거래 ID는 입력 모델에 존재하지 않습니다.

## 연결 원칙

### 연결되는 거래

Phase 4E의 `attempt_links`에서 다음 조건을 모두 만족하는 거래만 여정에 포함합니다.

- 상태가 `linked`
- 단말 가명이 정확히 하나임
- 연결 근거 프레임이 원 거래 근거와 정확히 일치함
- 거래 근거가 비어 있지 않음
- 거래 근거 프레임이 생략되지 않음
- 단말 보고서의 `linked_attempt_ids`와 연결 결과가 정확히 일치함

### 연결하지 않는 거래

다음 거래는 여정에 포함하지 않고 별도로 집계합니다.

- `unassigned`: 단말 L2 근거 없음
- `ambiguous`: 둘 이상의 단말 후보가 있음
- 근거 프레임이 일부 생략된 거래
- 연결 객체와 원 거래의 근거 프레임이 다름
- 잘못된 DEVICE/AP/거래 가명

RADIUS처럼 단말 주소가 보이지 않는 거래를 시간 근접성만으로 DEVICE-N에 연결하지 않습니다.

## 단계

여정은 다음 순서의 프로토콜 단계를 사용합니다.

```text
EAP
RADIUS
DHCP
DNS
TCP
```

표시 순서는 위 고정 순서가 아니라 **각 단계에서 처음 관찰된 실제 프레임 순서**입니다. 동일 단계의 여러 거래는 하나의 단계 요약으로 집계하되 각 거래 시도 ID를 그대로 제공합니다.

## 단계 상태

| 상태 | 의미 |
|---|---|
| `complete` | 연결된 거래에서 필요한 성공 순서가 관찰됨 |
| `success-observed` | 성공 결과 또는 성공 방향 응답이 관찰됨 |
| `failure-observed` | 실패·거부·오류·Reset이 관찰됨 |
| `mixed` | 같은 단계에 성공 방향과 실패 결과가 함께 있음 |
| `partial-progress` | 성공 방향 거래와 미완료 거래가 함께 있음 |
| `incomplete` | 요청·중간 이벤트만 있고 최종 결과가 없음 |

## 여정 상태

| 상태 | 의미 |
|---|---|
| `progress-observed` | 연결된 단계에서 성공 방향 진행이 관찰됨 |
| `failure-observed` | 한 개 이상 단계에서 명시적 실패 결과가 관찰됨 |
| `mixed` | 단계 안 또는 여정 전체에 성공과 실패가 혼재함 |
| `partial-progress` | 성공 방향 진행과 미완료 단계가 함께 있음 |
| `incomplete` | 연결 거래가 있으나 명시적 최종 결과가 없음 |
| `no-linked-transactions` | 단말은 관찰됐지만 안전하게 연결된 거래가 없음 |

## 결과

각 `DEVICE-N` 여정은 다음 내용을 제공합니다.

- 관찰 AP 가명
- 단말 첫·마지막 프레임과 상대 지속시간
- 안전하게 연결된 거래 시도 ID
- 실제 프레임 기준 관찰 단계 순서
- 단계별 상태·거래·근거 프레임
- 첫 실패 관찰 단계
- 마지막 성공 방향 단계
- Wireshark `frame.number` 근거 필터

## 판정 안전 경계

다음 값은 항상 `false`입니다.

```text
device_identity_confirmed
cross_protocol_session_confirmed
root_cause_confirmed
```

따라서 `DEVICE-1`에 DHCP·DNS·TCP 거래가 연결돼도 다음을 자동 확정하지 않습니다.

- 실제 사용자 신원
- 다른 분석 실행의 DEVICE-1과 동일한 장치
- EAP부터 TCP까지 하나의 연속 사용자 세션
- 전체 무선 접속 성공
- ClearPass·DHCP·DNS·방화벽·서버 중 근본 책임 시스템

“첫 실패 단계”는 명시적 실패 패킷이 처음 관찰된 위치이며 근본 원인의 위치가 아닙니다.

## 개인정보 보호

단말 가명 보고서에서 다음 보호 플래그가 하나라도 바뀌면 여정 생성을 거부합니다.

```text
raw_identifiers_serialized = false
alias_secret_persisted = false
aliases_stable_across_runs = false
```

결과에도 원본 식별정보, 가명화 키, 절대 epoch, 캡처 파일명과 절대경로를 기록하지 않습니다.

## 자원 제한

- 단말 가명 최대 20,000개
- 거래 시도 최대 50,000개
- 원 거래 근거 프레임 최대 64개
- 여정 및 단계 근거 프레임 최대 96개
- 잘못된 가명·중복 거래·연결 누락·근거 불일치는 실패-폐쇄 처리

## 생략 근거 처리

Phase 4D에서 근거 프레임 상한을 초과한 거래는 공개 보고서에 생략 수를 남깁니다. Phase 4E는 단말 연결용 임시 복사본에서 해당 근거를 비우고 `unassigned` 또는 `ambiguous`로 유지합니다.

Phase 4F는 이 정제된 미연결 상태만 허용합니다.

- 생략 거래 + 미연결 + 빈 연결 근거: 여정에서 제외하고 계속 분석
- 생략 거래 + `linked`: 즉시 거부
- 생략 거래 + 연결 근거 잔존: 즉시 거부

## 자동 검증

### 단위 테스트

- DHCP → DNS → TCP 실제 프레임 순서
- 첫 실패 단계와 마지막 성공 방향 단계
- 같은 단계의 성공·실패 혼재
- 미할당·모호 거래의 여정 제외
- 연결 거래 없는 단말 유지
- 일부 입력의 전체 완료 차단
- 결정론적 직렬화와 원문 식별정보 비노출
- 개인정보 플래그 변경 거부
- 연결 근거와 원 거래 근거 불일치 거부
- 생략 근거 미연결 거래 정상 제외
- 생략 근거 연결 거래 거부

### Portable 실제 패킷 검증

Python·Wireshark가 없는 실행 환경에서 최종 EXE로 런타임 생성 Ethernet PCAP을 분석합니다.

예상 `DEVICE-1` 결과:

- EAP 완료 거래
- DHCP DORA 완료 거래
- DNS 정상 거래
- TCP SYN/SYN-ACK 성공 방향 거래
- 별도 TCP RST 실패 거래
- TCP 단계 `mixed`
- 여정 첫 실패 단계 `tcp`
- 마지막 성공 방향 단계 `tcp`
- RADIUS는 단말 근거가 없어 여정에 시간 추정으로 추가하지 않음
- 원본 주소·거래 ID·가명화 키·절대 시간 비노출
- 분석 전후 Portable 폴더 무변경

Phase 4F는 단말 가명별 **관찰 여정**까지 제공합니다. 다음 단계에서는 캡처 시작·종료·방향·잘림·패킷 상한을 종합해 미관찰과 실제 미응답을 구분하는 캡처 완전성 모델을 강화합니다. 그 이후 동일 단말의 EAPOL 4-Way Handshake와 로밍·RF 분석, 오프라인 HTML 보고서를 진행합니다.
