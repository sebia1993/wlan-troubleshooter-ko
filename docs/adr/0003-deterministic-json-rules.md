# ADR 0003: 결정론적 JSON 규칙과 한국어 메시지

- 상태: 승인
- 날짜: 2026-09-03

## 배경

초급 네트워크 엔지니어에게 제공하는 진단은 쉬워야 하지만, 설명이 패킷 근거보다 앞서서는 안 됩니다. 코드에 조건과 문장을 섞으면 변경 검토와 회귀 테스트가 어렵고, 입력 순서·현재 시각·환경에 따라 출력이 달라지면 동일 장애를 재현하기 어렵습니다.

## 결정

분석 판정과 한국어 설명을 버전이 있는 JSON 리소스로 분리합니다.

- 규칙, 메시지, 사이트 중립 프로파일은 JSON으로 저장합니다.
- 각 파일에 `schema_version`과 콘텐츠 버전을 둡니다.
- 규칙 ID와 메시지 ID는 유일하고 안정적이어야 합니다.
- 알 수 없는 필드, 중복 ID, 잘못된 값은 자동 보정하지 않고 로딩 실패로 처리합니다.
- 규칙은 실행 코드나 표현식을 담지 않으며 `eval`과 `exec`를 사용하지 않습니다.
- Phase 1에서는 로더와 빈 골격만 만들고 실제 장애 판정 규칙은 추가하지 않습니다.

## 정규화 규칙

같은 입력 PCAP 해시, 같은 애플리케이션 버전, 같은 규칙 버전, 같은 TShark 버전에서는 같은 정규화 분석 JSON을 생성해야 합니다.

- 객체 키 순서를 고정합니다.
- Finding, 세션, 이벤트, 근거 프레임의 정렬 기준을 명시합니다.
- 현재 시각, 난수, 절대 파일 경로, 프로세스 ID를 분석 결과에 넣지 않습니다.
- 캡처 시각은 명시된 고정 형식으로 변환합니다.
- 기간과 비율은 가능한 한 고정 단위 정수로 표현합니다.
- 한국어 문자열과 사용자 입력은 일관된 유니코드 정규화를 적용합니다.
- UTF-8, 고정 separators, 고정 줄바꿈으로 직렬화합니다.
- 정규화 결과와 화면 표시용 일시적 상태를 분리합니다.

## 판정 수준

판정 수준은 다음 네 가지로 제한합니다.

- `확정`: 캡처에 명시적인 성공·실패 응답 또는 직접 오류 증거가 있고 필요한 문맥이 충족됩니다.
- `유력`: 여러 독립적인 관찰이 같은 장애 구간을 가리키지만 직접 실패 응답이 없거나 대안이 남아 있습니다.
- `참고`: 비특이적 관찰이 있어 추가 확인에 도움이 되지만 원인 판단 근거로는 부족합니다.
- `판단 불가`: 캡처 범위, 방향, 길이, 필요한 계층이 부족하거나 근거가 충돌합니다.

`판단 불가` 조건은 억지 진단보다 우선합니다. 패킷이 없다는 사실만으로 실패를 확정하지 않습니다.

## 근거 구조

각 Finding은 최소한 다음 의미를 분리해야 합니다.

- 관찰된 사실
- 제한사항
- 판정 수준
- 가능한 원인
- 다음 확인 위치
- 근거 프레임 번호
- 재현 가능한 Wireshark Display Filter
- 적용한 규칙 ID와 버전

Raw Payload와 자격 증명은 근거에 포함하지 않습니다. 근거 프레임은 숫자 순으로, Finding은 안정적인 심각도·단계·규칙 ID 순으로 정렬합니다.

## 충돌 처리

- 동일 대상에 상반된 직접 증거가 있으면 캡처 시간과 세션 경계를 먼저 분리합니다.
- 분리할 수 없으면 더 강한 결론을 선택하지 않고 `판단 불가`로 낮춥니다.
- 캡처 한계 규칙은 원인 규칙보다 먼저 평가합니다.
- TCP Retransmission, 단일 재시도, 패킷 부재 같은 비특이적 신호는 단독으로 RF·서버·ClearPass 장애를 확정할 수 없습니다.

## 테스트

각 실제 규칙은 이후 다음 네 종류의 테스트를 가져야 합니다.

- Positive: 필요한 직접 증거에서 기대한 판정이 생성됩니다.
- Negative: 비슷하지만 조건이 다른 입력에서 오판하지 않습니다.
- Ambiguous: 캡처가 불완전하면 `판단 불가`가 됩니다.
- Conflict: 상반된 근거가 있으면 정해진 안전 규칙을 따릅니다.

Phase 1에서는 JSON 키 순서가 달라도 같은 결과가 나오는지, 중복 ID와 잘못된 스키마가 거부되는지, 유니코드 정규화가 안정적인지를 테스트합니다.

## 결과

장점:

- 규칙 변경과 한국어 문장 검수를 분리할 수 있습니다.
- 같은 증거에서 같은 결과를 재현할 수 있습니다.
- 초급 사용자용 설명과 전문가 근거를 함께 유지할 수 있습니다.

제약:

- 자유로운 자연어 질문을 지원하지 않습니다.
- 새 장비·프로토콜·장애 유형은 규칙과 테스트를 추가해야 합니다.
- 결정론적 결과를 유지하려면 정렬·숫자·시간 형식을 엄격히 관리해야 합니다.
