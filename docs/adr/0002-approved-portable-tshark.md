# ADR 0002: 승인된 Portable TShark만 사용

- 상태: 승인
- 날짜: 2026-09-03

## 배경

PCAP 프로토콜 해석은 Wireshark 프로젝트의 TShark를 사용할 예정입니다. 시스템 설치본이나 사용자의 Wireshark 환경을 자동으로 사용하면 버전, 플러그인, 개인 설정에 따라 결과가 달라질 수 있습니다. 프로그램이 실행 중 인터넷에서 바이너리를 내려받는 방식은 무결성과 오프라인 원칙을 훼손합니다.

## 결정

프로그램 패키지에 대해 별도로 승인된 Portable TShark만 사용합니다.

- 실행 후보는 애플리케이션이 지정한 `vendor/wireshark/` 아래로 제한합니다.
- 시스템 설치 경로, 레지스트리, `PATH`를 자동 탐색하거나 대체 경로로 사용하지 않습니다.
- 승인 매니페스트에 버전, 상대경로, 파일 크기, SHA-256을 기록합니다.
- 실행 전에 실행 파일과 필수 DLL의 해시를 확인합니다.
- 매니페스트 누락, 파일 누락, 해시 불일치는 안전한 실패로 처리합니다.
- 프로그램과 빌드 스크립트는 TShark를 자동 다운로드하거나 교체하지 않습니다.

Phase 1의 매니페스트 검증은 내부 승인 절차로 전달된 매니페스트와 파일의 일관성을
확인하는 경계이며, 매니페스트 자체를 암호학적으로 인증하지는 않습니다. 따라서
`approval_reference` 문자열만으로 공급자를 신뢰해서는 안 됩니다. 실제 배포 전에는
승인 매니페스트를 서명하거나 애플리케이션에 고정하고, 일반 사용자가 수정할 수 없는
읽기 전용 패키지 경계로 공급하는 절차를 별도로 승인해야 합니다.

Phase 1에서는 매니페스트 로더, 해시 검증, 준비 상태, 인자 정책, 안전한 실패까지만 구현합니다. 승인 바이너리가 없는 상태에서 실제 패킷 분석이 검증되었다고 표시하지 않습니다. 실제 프로토콜 필드 추출은 Phase 2입니다.

## 실행 정책

- Phase 1의 유일한 실행은 캡처를 열지 않는 고정 `-n -v` 준비 확인입니다. 필드 추출 인자 배열과 격리 환경은 준비할 수 있지만 실행하지 않습니다.
- 저장 파일을 읽는 모든 분석 명령에 `-n`을 넣어 이름 해석을 끕니다.
- 실행 파일 경로와 옵션은 코드가 만든 허용 목록에서만 선택합니다.
- 사용자 입력을 전체 명령줄 문자열에 이어 붙이지 않습니다.
- 준비 확인에는 제한시간, 취소, 자식 프로세스 종료, 임시파일 격리를 적용합니다. 캡처 필드 추출 실행은 Phase 2에서 별도로 승인하고 검증합니다.
- 격리 루트는 애플리케이션 작업공간 아래의 미존재 경로에 배타 생성하고, 기존 설정·플러그인·extcap 파일이 있는 경로는 재사용하지 않습니다.
- 해시만 일치한 상태는 `무결성 확인됨·실행 확인 전`으로 표시하며, 고정 준비 확인이 실제로 성공하기 전에는 `실행 준비`로 표시하지 않습니다.
- 실시간 인터페이스 캡처와 원격 캡처를 허용하지 않습니다.
- `rpcap`, `TCP@호스트:포트`, 임의 extcap, 임의 Lua 스크립트, 임의 사용자 옵션을 허용하지 않습니다.
- 사용자 Wireshark 개인 설정과 플러그인을 읽지 않도록 승인 버전에서 검증된 격리 프로필과 환경만 사용합니다.
- Raw Payload, 쿠키, Authorization, 자격 증명을 요청하는 필드는 승인 목록에 넣지 않습니다.

## 라이선스와 공급망

TShark 바이너리는 현재 저장소에 포함하지 않습니다. 실제 배포 전에는 승인된 버전에 대해 다음을 완료해야 합니다.

- 공급 출처와 파일별 SHA-256 검증
- 구성요소와 DLL 목록 고정
- 저작권 고지와 라이선스 원문 포함
- 수정 여부 기록
- 해당 버전의 소스 제공·재배포 의무 검토와 이행
- Windows 패키지 내부에서 매니페스트와 실제 파일 재검증

## 결과

장점:

- TShark 버전과 필드 동작을 재현할 수 있습니다.
- 사용자의 설치 환경과 플러그인에 의한 변화를 줄입니다.
- 승인되지 않은 바이너리를 안전하게 거부할 수 있습니다.

제약:

- 승인된 번들이 없으면 분석 기능을 사용할 수 없습니다.
- Wireshark 보안 업데이트는 자동 적용되지 않으며 새 버전 승인과 릴리스가 필요합니다.
- DLL, 플러그인, 프로필까지 포함한 실제 격리는 Windows 배포본에서 별도 검증해야 합니다.
